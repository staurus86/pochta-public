<objective>
Fix two product-name quality gaps:

1. **PROD-01 — Numbered list cleanup**: The existing `productNames[].name` inline cleanup at `email-analyzer.js` lines 1573–1579 strips `"N. "` prefix and em/en-dash qty tail (`— N шт`). However emails using a plain hyphen separator (`"Клапан - 5 шт"`) bypass the qty-tail strip because the regex requires an optional `[-–—]?` followed by `\s*\d+` — but the regex is applied AFTER stripping the leading `"N. "`, so the remaining full line with hyphen-qty survives. Add a safety-net replace for the plain-hyphen case after the existing chain.

2. **PROD-02 — HTML-residue dedup**: `canonicalNameKey()` in `email-analyzer.js` (lines 1522–1538) builds the dedup key without stripping HTML residue. Two `productNames[]` entries differing only by `<br>` or `&amp;` produce different canonical keys and survive as duplicates. Fix: add `stripHtmlResidue()` as the first step inside `canonicalNameKey`, and add it to the import from `product-name-normalizer.js`.

3. **Audit script bug fix**: `check_product_name` in `scripts/audit_baseline.py` applies `NUMBERED_LIST_RE` against `str(n)` where `n` is a Python dict. Because `str(dict)` starts with `{`, the regex never matches. Fix: use `n.get("name", "") if isinstance(n, dict) else str(n)` to extract the `.name` field.

Purpose: Eliminate numbered-list-format strings from `productNames[]`, remove HTML-residue duplicate entries, and make the audit script correctly measure product_name noise so Phase 14 improvements are visible in baseline_v4.

Output: Modified `email-analyzer.js`, `audit_baseline.py`, mirrored `email-analyzer.js` to `.railway-deploy/`, appended tests to `tests/batch-14-fixes.test.js`.
</objective>
