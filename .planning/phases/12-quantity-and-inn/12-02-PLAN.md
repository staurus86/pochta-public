<objective>
Add FNS mod-11 INN checksum validation (CONTACT-02). Currently `normalizeInn()` (email-analyzer.js:254) accepts ANY 9/10/12-digit string with no checksum, so corrupt 10-digit numbers pass through as INNs and 10-digit numbers with "strong article context" leak into the articles array. This plan adds `validateInnChecksum(digits)`, gates `normalizeInn()` on it (return null on failure), and updates `isObviousArticleNoise()` so a checksum-fail 10-digit number is rejected as both INN and article.

Purpose: Honest `sender.inn` (no corrupt 10-digit values) and no 10-digit INN leaking into articles. Because all body/form INN paths flow through `normalizeInn`, this single hook covers them.
Output: `validateInnChecksum()` in email-analyzer.js, checksum-gated `normalizeInn()`, updated article-noise rule, new tests in `tests/batch-12-fixes.test.js`, mirror to .railway-deploy.
</objective>

    ```javascript
    export function validateInnChecksum(digits) {
        const s = String(digits || "").replace(/\D/g, "");
        if (s.length === 9) return true; // Belarus УНП — no checksum
        const d = s.split("").map(Number);
        if (d.some((x) => Number.isNaN(x))) return false;
        if (s.length === 10) {
            const w = [2, 4, 10, 3, 5, 9, 4, 6, 8, 0];
            const sum = w.slice(0, 9).reduce((acc, wi, i) => acc + wi * d[i], 0);
            return d[9] === (sum % 11) % 10;
        }
        if (s.length === 12) {
            const w1 = [7, 2, 4, 10, 3, 5, 9, 4, 6, 8, 0];
            const w2 = [3, 7, 2, 4, 10, 3, 5, 9, 4, 6, 8, 0];
            const c1 = (w1.slice(0, 11).reduce((acc, wi, i) => acc + wi * d[i], 0) % 11) % 10;
            const c2 = (w2.slice(0, 12).reduce((acc, wi, i) => acc + wi * d[i], 0) % 11) % 10;
            return d[10] === c1 && d[11] === c2;
        }
        return false;
    }
    ```
