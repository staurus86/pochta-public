# Requirements — v1.1 Detection Quality Sprint

**Milestone:** v1.1
**Status:** Defined
**Date:** 2026-05-25

---

## In Scope

### AUDIT — Аудит и метрика

- [x] **AUDIT-01**: Агенты проводят ручной аудит 50 реальных писем из продакшна, фиксируя ошибки детекции по каждому полю (ФИО, ИНН, телефон, артикул, бренд, кол-во, название товара) → structured bug report
- [x] **AUDIT-02**: Автоматический audit-скрипт измеряет % писем с корректным значением по каждому полю — baseline перед фиксами и после каждого
- [x] **AUDIT-03**: n8n фидбек (оценки менеджера) загружается через GET-эндпоинт и используется как входные данные для аудита

### ART — Артикулы и количество

- [x] **ART-01**: Zone-aware `article-extractor.js` подключается в `extractLead()` внутри `email-analyzer.js` вместо 500-строчного inline regex-каскада, устраняя мусор из подписей и цитат
- [x] **ART-02**: UUID-токены и form-метаданные (hex 32+ символов, UUID v4) отклоняются как артикулы
- [x] **ART-03**: Ключ дедупликации нормализует пробел и дефис — `MD-025-6L` эквивалентен `MD 025-6L`
- [ ] **ART-04**: `positions` равно числу уникальных артикулов, `totalQty` равно сумме количеств по уникальным позициям (Belgormash bug: было 18/7, должно быть 2/5)

### CONTACT — Контактные данные

- [ ] **CONTACT-01**: ИНН из текста вложений-реквизитов (PDF/DOCX карточки контрагента) пробрасывается в `sender.inn` при отсутствии ИНН в теле письма
- [ ] **CONTACT-02**: Валидация ИНН по контрольной сумме (mod-11, официальный алгоритм ФНС) — 10-значные числа не прошедшие checksum отклоняются как артикулы и не принимаются как ИНН
- [ ] **CONTACT-03**: ФИО из шаблона формы robot@siderus.ru (например, «Екатерина Попова») не используется как ФИО клиента — блок-лист имён определяется по контексту отправителя
- [ ] **CONTACT-04**: Телефон: поддержка международных форматов +375 (Беларусь), +86 (Китай), +994 (Азербайджан) через `libphonenumber-js/min`

### BRAND — Бренды

- [ ] **BRAND-02**: Бренды, найденные в строке `Subject` письма, получают повышенный приоритет при детекции (subject = явный сигнал запроса)
- [ ] **BRAND-03**: Алиасы бренда длиной ≤ 3 символа отклоняются при детекции как слишком короткие (высокий риск ложных срабатываний)

### PROD — Названия товаров

- [ ] **PROD-01**: Сырой формат нумерованного списка `"1. Название товара — N шт."` убирается из массива `productNames`
- [ ] **PROD-02**: Дедупликация `productNames` после нормализации: строки, отличающиеся только HTML-остатком или пунктуацией, сворачиваются в одну

## Future Requirements (deferred)

- ФИО: русские суффиксы фамилий в scoring (`-ов/-ова/-ский`) — улучшит точность, но не критично для MVP
- Бренды: fuzzy matching по Levenshtein для опечаток — сложность выше, отложить после baseline измерения
- ИНН: автоматический поиск ИНН по названию компании через внешнее API — вне scope (external API)
- Архитектура: автоматическая синхронизация `src/` ↔ `.railway-deploy/src/` — важно, но не влияет на accuracy

---

## Out of Scope

- LLM-классификация и извлечение (отключена из-за стоимости) — возможно в milestone v1.2 когда найдут API
- Directus-интеграция — заменена на n8n, не возвращаемся
- OCR вложений-сканов — нет подходящего API
- v2 монорепо (Next.js/Fastify/BullMQ) — до аудита не трогаем
